في الدرسين السابقين استخدمنا الاستدعاء ضمن أول k نتائج: هل الصحيح بينها؟ ومعه مقياسان مهمان:

الترتيب مع درجات أهمية

الرتبة المعكوسة تهتم بأول نتيجة مفيدة فقط. إذا كانت عدة نتائج مفيدة، وبعضها أهم من بعض، نستخدم مقياساً يعطي كل نتيجة وزناً حسب أهميتها، ويخصمه حسب رتبتها:

DCG@k=∑i=1krelilog⁡2(i+1)

ثم نقسم على أفضل قيمة ممكنة: كل المستندات المفيدة المعروفة، مرتبة ترتيباً مثالياً. فيصبح الرقم بين صفر وواحد.

مثال: ثلاث نتائج، المفيدة منها الأولى والثالثة:

DCG=1log⁡22+0+1log⁡24=1+0.5=1.5

والترتيب المثالي يضع المفيدتين أولاً:

IDCG=1+1log⁡23=1.631,nDCG=1.51.631=0.920

النموذج حكَماً

إذا كانت المقاييس البسيطة لا تفهم المعنى، فلنستخدم شيئاً يفهمه: نموذجاً لغوياً آخر، مع معايير مكتوبة.

نعطيه: السؤال، والمصادر، والجواب المرجعي إن وجد، وجواب النظام. ويرجع حكماً بصيغة محددة.

LLM-as-a-judge · rubric

نصائح تجعل الحكَم أفضل:

  1. معايير واضحة ومحددة: "صحيح إذا اتفق مع المصادر في كل معلومة"، لا "هل الجواب جيد؟".
  2. السبب قبل الحكم: اطلب منه أن يكتب السبب أولاً، ثم الحكم. يفكّر قبل أن يقرر.
  3. صيغة ثابتة: كائن بحقول محددة، يُحلَّل بالكود.
  4. مخرجات منظمة: اطلب من الواجهة أن يلتزم الرد بمخطط جيسون، كما في الدرس 54. وقِس الثبات: شغّل الحكَم مرتين على نفس العينة، وقارن.
  5. حكم ثنائي أو مقياس صغير: "صحيح أو خطأ" أثبت من درجة من واحد إلى عشرة.

قياس الاتفاق: معامل كابا

نسبة الاتفاق البسيطة تخدع: إذا كانت أغلب الأجوبة صحيحة، فحكَم يقول "صحيح" دائماً يتفق كثيراً مع البشر، وهو عديم الفائدة.

معامل كابا يخصم الاتفاق المتوقع بالصدفة:

κ=po−pe1−pe

حيث po نسبة الاتفاق الفعلي، و pe نسبة الاتفاق المتوقعة لو حكم كل منهما عشوائياً بنفس نسبه.

def light_stem(w):
    for p in ("وال", "بال", "كال", "فال", "لل", "ال"):
        if w.startswith(p) and len(w) - len(p) >= 2:
            w = w[len(p):]
            break
    for _ in range(2):
        for s in ("ات", "ون", "ين", "ها", "هم", "كم", "ني", "ه", "ي", "ك", "ا"):
            if w.endswith(s) and len(w) - len(s) >= 3:
                w = w[:-len(s)]
                break
    return w

def terms(text):
    return [light_stem(w) for w in re.findall(r"\w+", normalize(text))]

class BM25:
    def __init__(self, texts, k1=1.5, b=0.75):
        self.docs = [Counter(terms(t)) for t in texts]
        self.lens = [sum(d.values()) for d in self.docs]
        self.avg = sum(self.lens) / len(self.lens)
        self.k1, self.b = k1, b
        N = len(texts)
        df = Counter(w for d in self.docs for w in d)
        self.idf = {w: math.log((N - n + 0.5) / (n + 0.5) + 1) for w, n in df.items()}

    def scores(self, query):
        q = terms(query)
        out = np.zeros(len(self.docs))
        for i, (tf, L) in enumerate(zip(self.docs, self.lens)):
            for w in q:
                if w in tf:
                    f = tf[w]
                    out[i] += self.idf[w] * f * (self.k1 + 1) / (f + self.k1 * (1 - self.b + self.b * L / self.avg))
        return out

def pieces(text):
    out = []
    for w in re.findall(r"\w+", text.lower()):
        w = f"<{w}>"
        for n in (2, 3, 4):
            out += [w[i:i + n] for i in range(len(w) - n + 1)]
    return out

class TinyEncoder(nn.Module):
    def __init__(self, dim=64):
        super().__init__()
        self.table = nn.EmbeddingBag(BUCKETS, dim, mode="mean")
        nn.init.normal_(self.table.weight, std=0.1)

    def forward(self, batch):
        flat, starts = [], []
        for text in batch:
            starts.append(len(flat))
            flat += [zlib.crc32(p.encode()) % BUCKETS for p in pieces(text)]
        return F.normalize(self.table(torch.tensor(flat), torch.tensor(starts)), dim=-1)

def retrieval_report(score_fn, questions=test_q, cutoff=10):
    ranks = []
    for q, gold in questions:
        order = np.argsort(-score_fn(q), kind="stable")
        ranks.append(int(np.where(order == index[gold])[0][0]) + 1)
    ranks = np.array(ranks)
    rr = np.where(ranks <= cutoff, 1 / ranks, 0.0)           # reciprocal rank, zero beyond the cutoff
    report = {f"recall@{k}": round(float((ranks <= k).mean()), 2) for k in (1, 3, 5)}
    report["MRR"] = round(float(rr.mean()), 3)
    return report

def answer_tokens(text):
    text = re.sub(r"\[\d+\]", " ", text)                        # citation numbers are not part of the answer
    text = re.sub(r"[^\w\s]", " ", normalize(text))             # punctuation
    out = []
    for w in text.split():
        for p in ("وال", "بال", "لل", "ال"):
            if w.startswith(p) and len(w) - len(p) >= 2:
                w = w[len(p):]
                break
        out.append(w)
    return out

def exact_match(pred, gold):
    return float(answer_tokens(pred) == answer_tokens(gold))

def token_f1(pred, gold):
    p, g = answer_tokens(pred), answer_tokens(gold)
    common = sum((Counter(p) & Counter(g)).values())
    if common == 0:
        return 0.0
    precision, recall = common / len(p), common / len(g)
    return 2 * precision * recall / (precision + recall)

def contains(pred, gold):
    p, g = answer_tokens(pred), answer_tokens(gold)
    return float(any(p[i:i + len(g)] == g for i in range(len(p) - len(g) + 1)))

def cohen_kappa(a, b):
    a, b = np.asarray(a, float), np.asarray(b, float)
    po = (a == b).mean()                                        # observed agreement
    pe = a.mean() * b.mean() + (1 - a.mean()) * (1 - b.mean())  # agreement expected by chance
    return (po - pe) / (1 - pe)

def parse_verdict(text):
    match = re.search(r"\{.*\}", text, flags=re.S)             # the model may add words around the JSON
    try:
        verdict = json.loads(match.group(0))["verdict"]
    except (AttributeError, ValueError, KeyError):
        return None                                              # unparseable: count it, never guess
    return {"correct": 1, "incorrect": 0}.get(str(verdict).lower())

سؤال مقابلة

سؤال قد تسمعه في المقابلة:

How would you evaluate a RAG-based chatbot?

جواب قصير وجيد:

Build a golden set of real user questions with their relevant documents and reference answers. Evaluate retrieval separately with recall@k and MRR, then evaluate answers with cheap automated checks such as format, citation validity, and number grounding, plus an LLM judge with a clear rubric for correctness and faithfulness to the sources. Calibrate the judge against human labels on a sample, run the whole suite on every change as a regression test, and monitor online signals after deployment.

سؤال قد تسمعه في المقابلة:

What are the limitations of exact match and token F1 for LLM outputs?

جواب قصير وجيد:

Exact match is too strict for free-form answers, since correct paraphrases score zero. Token F1 rewards word overlap rather than meaning: a verbose correct answer and a short wrong answer can get the same score, and errors outside the reference span are invisible. They are useful as cheap trend signals, not as the final measure of correctness.

سؤال قد تسمعه في المقابلة:

What are the risks of using an LLM as a judge, and how do you mitigate them?

جواب قصير وجيد:

Judges show position bias in pairwise comparisons, verbosity bias, self-preference for their own model family, and ordinary mistakes. Mitigate with a specific rubric, reasoning before the verdict, structured output with a JSON schema, checking consistency across repeated runs, swapping the order in pairwise comparisons, a judge from a different family, and by measuring agreement with human labels using a chance-corrected metric such as Cohen's kappa.

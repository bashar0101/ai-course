مشكلة الوادي الضيق

النزول بالتدرّج العادي يأخذ خطوة عكس التدرّج، بنفس معدل التعلّم لكل المعاملات.

هذا يعمل جيداً عندما تكون الخسارة على شكل وعاء دائري. لكنها غالباً على شكل وادٍ ضيق:

شديد الانحدار في اتجاه، وشبه مستوٍ في اتجاه آخر.

في هذا الوادي:

  • معدل تعلّم كبير: الخطوات تقفز بين جداري الوادي، وقد تنفجر.
  • معدل تعلّم صغير: التقدم على طول الوادي بطيء جداً.

المحسّنات الحديثة حلّ لهذه المشكلة. جرّب قبل أن نشرح:

هنا أداة تفاعلية. إذا لم تظهر، حدّث الصفحة.

الزخم

الفكرة: كرة تتدحرج في الوادي. لا تتوقف عند كل خطوة، بل تحمل سرعتها.

نحتفظ بـ"سرعة" v، ونضيف إليها التدرّج في كل خطوة:

v←βv+g
w←w−η v

الرمز η هو معدل التعلّم، و β معامل الزخم، وقيمته المعتادة 0.9.

  • في الاتجاه الثابت: التدرّجات تتجمع، فتتسارع الخطوات.
  • في الاتجاه المتذبذب: التدرّجات تتعاكس، فتلغي بعضها.
momentum

آدم

الزخم يستخدم معدل تعلّم واحداً لكل المعاملات. لكن بعض المعاملات تدرّجاتها كبيرة دائماً، وبعضها صغيرة.

آدم يعطي كل معامل خطوة خاصة به: يقسم على حجم تدرّجاته المعتاد.

يتابع رقمين لكل معامل. الأول متوسط التدرّج، مثل الزخم:

m←β1m+(1−β1) g

والثاني متوسط مربع التدرّج، أي حجمه المعتاد:

s←β2s+(1−β2) g2

ثم يصحح انحياز البداية، لأن المتوسطين يبدآن من صفر:

m^=m1−β1t,s^=s1−β2t

والخطوة:

w←w−η m^s^+ϵ

القيم المعتادة: β1=0.9، و β2=0.999، و ϵ رقم صغير جداً يمنع القسمة على صفر.

القسمة على s^ هي السر: معامل تدرّجاته كبيرة يأخذ خطوات أصغر، ومعامل تدرّجاته صغيرة يأخذ خطوات أكبر.

معدل التعلّم

معدل التعلّم أهم معامل فائق في التعلّم العميق. إذا كان عندك وقت لضبط شيء واحد، اضبطه.

كيف تختاره؟ جرّب قيماً على مقياس لوغاريتمي: 0.0001، و 0.001، و 0.01، و 0.1، و 1. درّب قليلاً بكل قيمة، وقارن الخسارة.

ستجد شكل حرف U: الصغيرة جداً بطيئة، والكبيرة جداً غير مستقرة، والأفضل في المنتصف.

وسنرى ذلك بالأرقام في الكود.

حجم الأوزان مهم

في كل طبقة، مخرج العصبون مجموع حواصل ضرب كثيرة. إذا كانت الأوزان كبيرة قليلاً، يكبر المخرج طبقة بعد طبقة، حتى ينفجر.

وإذا كانت صغيرة قليلاً، يصغر حتى يختفي. ومع اختفاء المخرجات تختفي التدرّجات أيضاً.

طبقات التطبيع

حتى مع تهيئة جيدة، تتغير أحجام القيم داخل الشبكة أثناء التدريب.

طبقة التطبيع تعيد القيم إلى مقياس ثابت: متوسط صفر، وانحراف معياري واحد. تماماً مثل توحيد المقاييس في الدرس 17، لكن داخل الشبكة.

x^i=xi−μσ2+ϵ,yi=γ x^i+β

المعاملان γ و β متعلّمان: يسمحان للشبكة أن تختار المقياس المناسب بنفسها.

الفرق بين النوعين المشهورين: على أي بُعد نحسب المتوسط.

import math
import numpy as np
import torch
from torch import nn

def two_steps(momentum):
    w = torch.tensor(1.0, requires_grad=True)
    opt = torch.optim.SGD([w], lr=0.1, momentum=momentum)
    for _ in range(2):
        loss = w ** 2
        opt.zero_grad(); loss.backward(); opt.step()
    return round(w.item(), 4)

print("plain SGD after 2 steps:", two_steps(0.0))
print("momentum  after 2 steps:", two_steps(0.9))

spiral_setup.pyبايثون
from torch.utils.data import DataLoader, TensorDataset

def make_spiral(n_per_class=100, n_classes=3, noise=0.2, seed=0):
    rng = np.random.default_rng(seed)
    X, y = [], []
    for k in range(n_classes):
        r = np.linspace(0.0, 1.0, n_per_class)
        t = np.linspace(4 * k, 4 * (k + 1), n_per_class) + rng.normal(0, noise, n_per_class)
        X.append(np.column_stack([r * np.sin(t), r * np.cos(t)]))
        y.append(np.full(n_per_class, k))
    return np.vstack(X), np.concatenate(y)

X, y = make_spiral()
idx = np.random.default_rng(1).permutation(len(X))
X_tr = torch.tensor(X[idx[:240]], dtype=torch.float32)
y_tr = torch.tensor(y[idx[:240]])
X_val = torch.tensor(X[idx[240:]], dtype=torch.float32)
y_val = torch.tensor(y[idx[240:]])
loss_fn = nn.CrossEntropyLoss()

def make_model():
    torch.manual_seed(0)                           # same initial weights every time
    return nn.Sequential(nn.Linear(2, 64), nn.ReLU(), nn.Linear(64, 3))

def train(make_opt, epochs=100):
    model = make_model()
    opt = make_opt(model.parameters())
    loader = DataLoader(TensorDataset(X_tr, y_tr), batch_size=32, shuffle=True,
                        generator=torch.Generator().manual_seed(0))
    history = []
    for _ in range(epochs):
        model.train()
        for xb, yb in loader:
            loss = loss_fn(model(xb), yb)
            opt.zero_grad(); loss.backward(); opt.step()
        model.eval()
        with torch.no_grad():
            history.append(loss_fn(model(X_tr), y_tr).item())
    with torch.no_grad():
        acc = (model(X_val).argmax(1) == y_val).float().mean().item()
    return history, acc

schedules.pyبايثون
steps, warmup, lr_max = 1000, 100, 0.1

def warmup_cosine(t):
    if t < warmup:
        return (t + 1) / warmup                              # linear warmup
    progress = (t - warmup) / (steps - warmup)
    return 0.5 * (1 + math.cos(math.pi * progress))          # cosine decay

def lr_curve(make_scheduler):
    opt = torch.optim.SGD([torch.zeros(1, requires_grad=True)], lr=lr_max)
    sched = make_scheduler(opt)
    values = []
    for _ in range(steps):
        values.append(opt.param_groups[0]["lr"])
        opt.step(); sched.step()                           # once per training step
    return values

curves = {
    "step decay": lr_curve(lambda o: torch.optim.lr_scheduler.StepLR(o, step_size=400, gamma=0.1)),
    "cosine": lr_curve(lambda o: torch.optim.lr_scheduler.CosineAnnealingLR(o, T_max=steps)),
    "warmup + cosine": lr_curve(lambda o: torch.optim.lr_scheduler.LambdaLR(o, warmup_cosine)),
}
for name, c in curves.items():
    print(f"{name:16}: step 0 → {c[0]:.4f}, step 50 → {c[50]:.4f}, step 500 → {c[500]:.4f}, step 999 → {c[999]:.5f}")

سؤال مقابلة

سؤال قد تسمعه في المقابلة:

What is the difference between SGD with momentum and Adam?

جواب قصير وجيد:

Momentum keeps an exponential average of past gradients and moves along it, which speeds up progress in consistent directions and damps oscillations. Adam also keeps a momentum-like average of gradients, but it additionally divides each parameter's step by a running estimate of the gradient's magnitude, so every parameter gets its own effective learning rate. Adam is less sensitive to the learning rate and to feature scale, which is why it is the common default.

سؤال قد تسمعه في المقابلة:

Why do we use learning rate warmup?

جواب قصير وجيد:

At the start of training the weights are random and Adam's moment estimates are noisy, so large steps can destabilize training. Warmup starts with a small learning rate and increases it linearly for the first steps, then a decay schedule such as cosine takes over. It is standard for transformers.

سؤال قد تسمعه في المقابلة:

Why not initialize all weights to zero?

جواب قصير وجيد:

All neurons in a layer would compute the same output and receive the same gradient, so they would stay identical forever. Random initialization breaks the symmetry. The scale also matters: He initialization, with standard deviation sqrt(2 / fan_in), keeps activations stable through ReLU layers.

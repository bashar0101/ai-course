المشكلة: نفس المعنى، بكلمات أخرى

عيادة فيها 24 صفحة أسئلة شائعة: الدوام، والأسعار، والحجز، وغيرها. مريض يكتب سؤاله، ونريد الصفحة التي تجيبه.

هذه العيادة خيالية، وسنستخدم بياناتها في هذا الدرس، وفي الدرسين التاليين.

البحث بالكلمات يعطي كل صفحة درجة حسب الكلمات المشتركة مع السؤال، كما في الدرس 19. لكن انظر:

السؤالالصفحة الصحيحةكلمات مشتركة
كم تكلفة الكشف؟الأسعار: المعاينة عند طبيب عام 400 ليرةلا شيء
طلب مني الطبيب رنيناً مغناطيسياًالأشعة: الرنين المغناطيسي غير متوفرلا شيء
ما عنوانكم؟العنوان: العيادة في شارع الورد رقم 12لا شيء

مشكلتان:

  1. المرادفات: تكلفة وسعر، كشف ومعاينة. كلمات مختلفة، والمعنى واحد.
  2. صرف العربية: نفس الكلمة بأشكال كثيرة. الرنين ورنيناً، العنوان وعنوانكم. البحث الحرفي يراها كلمات مختلفة.

والأسوأ: في السؤال الثالث، الكلمة المشتركة الوحيدة مع أي صفحة هي "ما". فيختار البحث صفحة الدوام، لأن فيها "ما عدا".

الحل: نحوّل كل نص إلى متجه، بحيث تكون النصوص المتقاربة في المعنى متقاربة في المتجه. عندها يصبح البحث: أوجد أقرب المتجهات لمتجه السؤال.

semantic search · sentence embedding

متجه واحد لكل نص

في الدرس 44: متجه لكل كلمة. وفي الدرس 48: الترانسفورمر يعطي متجهاً لكل رمز، يعرف سياق الجملة كلها.

لمتجه واحد للنص كله، ندمج متجهات الرموز. ومن أشيع الطرق: المتوسط. ثم نجعل طوله واحداً، فيصبح الضرب النقطي هو جيب التمام نفسه، كما في الدرس 44.

mean pooling · normalize

مرحلتان:

  1. مسبقاً: نرمّز كل المستندات مرة واحدة، ونخزن متجهاتها.
  2. مع كل سؤال: نرمّز السؤال فقط، ونحسب جيب التمام مع كل المتجهات المخزنة. هذا ضرب مصفوفات واحد.
bi-encoder
السر: السؤال والمستند يُرمَّزان كلاً وحده. لذلك متجهات المستندات تُحسب مرة واحدة، حتى لو كانت مليوناً. والسؤال يكلّف تمريرة واحدة فقط.

كيف يتعلم النموذج أن المعنى واحد؟

نموذج لغوي مدرّب مسبقاً، مثل نموذجنا في الدرس 49، تعلّم توقع الرمز التالي. متجهاته تحمل معنى، لكنه لم يتدرب لكي يقترب "كم تكلفة الكشف؟" من صفحة الأسعار.

لذلك نماذج التضمين تأخذ تدريباً إضافياً على أزواج: سؤال ومقطع يجيبه، جملة وترجمتها، عنوان ومقاله. مئات الملايين من الأزواج.

والهدف: متجها الزوج الواحد أقرب لبعضهما من أي زوج آخر.

الدفعة كلها أمثلة سلبية

خذ دفعة من B أزواج. رمّز الأسئلة، ورمّز المستندات، واحسب كل التشابهات: مصفوفة B×B.

القطر هو الأزواج الصحيحة، وكل ما عداه خطأ.

كل صف صار مسألة تصنيف: أي المستندات هو مستندي؟ فنستخدم السوفتماكس والإنتروبيا المتقاطعة، كما في الدرس 14.

والأمثلة السلبية مجانية: هي مستندات الأسئلة الأخرى في نفس الدفعة.

ثلاثة أسئلة، ولكل سؤال صفحته الصحيحة:

  1. كم تكلفة الكشف؟ صفحته: الأسعار.

القسمة على الحرارة

مع τ=0.1، كل رقم يُضرب في 10. الصف الثاني يصبح:

3,  5,  4
السوفتماكس على الصف الثاني
p=e5e3+e5+e4=1e−2+1+e−1=10.135+1+0.368=0.665

الخسارة:

−ln⁡0.665=0.408
الصفان الآخران

الصف الأول يصبح 6,2,1. احتمال الصحيح 0.976، والخسارة 0.025.

الصف الثالث يصبح 1,3,7. احتمال الصحيح 0.980، والخسارة 0.021.

متوسط الخسارة للدفعة:

0.025+0.408+0.0213=0.151

النموذج واثق في السؤالين الأول والثالث. التعلم الحقيقي في السؤال الثاني.

إلى أين يدفع التدرّج؟

من الدرس 37: تدرّج الإنتروبيا المتقاطعة بالنسبة للدرجات هو p−y. للصف الثاني:

p=(0.090,  0.665,  0.245),y=(0,  1,  0)
p−y=(0.090,  −0.335,  0.245)

الإشارة السالبة على الصفحة الصحيحة: ارفع تشابهها.

وأكبر قيمة موجبة على صفحة العنوان، 0.245: النزول بالتدرّج يخفض تشابهها أكثر من غيرها. الصفحة الخاطئة الأكثر إرباكاً تُدفع بعيداً أكثر من غيرها.

لماذا الحرارة؟

بدون حرارة، أي τ=1، الصف الثاني يبقى 0.3,0.5,0.4، واحتمال الصحيح 0.367 فقط. مع أنه الأول في الترتيب!

والمشكلة أعمق: جيب التمام لا يتجاوز 1. حتى نموذج مثالي، يعطي 1 للصحيح وسالب 1 للباقي، لا يتجاوز:

e1e1+2 e−1=0.787

فالخسارة لا تقترب من الصفر أبداً. القسمة على حرارة صغيرة توسّع مدى الدرجات، فيستطيع النموذج أن يكون واثقاً.

هنا أداة تفاعلية. إذا لم تظهر، حدّث الصفحة.

النماذج الحقيقية تستخدم حرارة صغيرة، بين 0.01 و 0.1 تقريباً. وبعضها يتعلم الحرارة نفسها أثناء التدريب.

import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

def evaluate(score_fn, questions, ks=(1, 3)):
    ranks = []
    for question, gold in questions:
        order = np.argsort(-score_fn(question), kind="stable")       # best page first
        ranks.append(int(np.where(order == index[gold])[0][0]) + 1)   # position of the right page
    ranks = np.array(ranks)
    return {f"recall@{k}": round(float((ranks <= k).mean()), 2) for k in ks}

word_vec = TfidfVectorizer()                      # one feature per word

    return (word_vec.transform([question]) @ word_docs.T).toarray()[0]

hashing trick
tiny_encoder.pyبايثون
import re
import zlib
import torch
import torch.nn as nn
import torch.nn.functional as F

BUCKETS = 2 ** 15

def pieces(text):
    """character pieces of every word, with word edges: <word> gives <w, wo, or, ..."""
    out = []
    for w in re.findall(r"\w+", text.lower()):
        w = f"<{w}>"
        for n in (2, 3, 4):
            out += [w[i:i + n] for i in range(len(w) - n + 1)]
    return out

class TinyEncoder(nn.Module):
    def __init__(self, dim=64):
        super().__init__()
        self.table = nn.EmbeddingBag(BUCKETS, dim, mode="mean")    # one vector per piece; a text is their mean
        nn.init.normal_(self.table.weight, std=0.1)

    def forward(self, batch):
        flat, starts = [], []
        for text in batch:
            starts.append(len(flat))
            flat += [zlib.crc32(p.encode()) % BUCKETS for p in pieces(text)]   # piece -> row number
        v = self.table(torch.tensor(flat), torch.tensor(starts))
        return F.normalize(v, dim=-1)                                # length 1: dot product = cosine

print(pieces("رنيناً")[:6], "...")

for step in range(201):
    chosen = rng.choice(len(docs), size=batch, replace=False)      # 16 different pages
    qs = [rng.choice(questions_of[ids[j]]) for j in chosen]       # one question for each
    Q, D = encoder(qs), encoder([texts[j] for j in chosen])
    logits = Q @ D.T / tau                                         # 16 x 16 similarities
    loss = F.cross_entropy(logits, torch.arange(batch))            # the right page is on the diagonal
    opt.zero_grad()
    loss.backward()
    opt.step()
    if step % 50 == 0:
        print(f"step {step:3}  loss {loss.item():.3f}")

print("after training, train questions:", evaluate(encoder_scores, train_q))
print("after training, test questions :", evaluate(encoder_scores, test_q))

approximate nearest neighbors · IVF

نجرب على 200 ألف متجه صناعي. صنعناها في مجموعات حسب الموضوع، كما تتجمع التضمينات الحقيقية:

ivf_search.pyبايثون
from sklearn.cluster import KMeans

rng = np.random.default_rng(0)
N, dim, k = 200_000, 64, 10
topics = rng.normal(size=(1000, dim))
X = topics[rng.integers(1000, size=N)] + 0.6 * rng.normal(size=(N, dim))
X = (X / np.linalg.norm(X, axis=1, keepdims=True)).astype(np.float32)
queries = X[rng.choice(N, 200, replace=False)] + 0.05 * rng.normal(size=(200, dim)).astype(np.float32)
queries /= np.linalg.norm(queries, axis=1, keepdims=True)

exact = np.argpartition(-(queries @ X.T), k, axis=1)[:, :k]      # brute force: the true top 10

kmeans = KMeans(n_clusters=256, n_init=1, max_iter=20, random_state=0).fit(X[:50_000])
group = kmeans.predict(X)
members = [np.where(group == g)[0] for g in range(256)]
centers = kmeans.cluster_centers_

for n_groups in (1, 4, 16):
    found = compared = 0
    for q, truth in zip(queries, exact):
        nearest = np.argsort(-(centers @ q))[:n_groups]              # the closest group centers
        cand = np.concatenate([members[g] for g in nearest])
        top = cand[np.argpartition(-(X[cand] @ q), k)[:k]]
        found += len(set(top) & set(truth))
        compared += len(cand)
    print(f"groups searched {n_groups:2}: found {found / (k * len(queries)):.1%} of the true top 10, "
          f"compared with {compared / len(queries) / N:.2%} of the vectors")

PostgreSQL · pgvector
pgvector.sqlقاعدة البيانات
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE pages (
    id        bigserial PRIMARY KEY,
    content   text NOT NULL,
    embedding vector(384) NOT NULL          -- the size of your embedding model
);

-- approximate search index for cosine distance
CREATE INDEX ON pages USING hnsw (embedding vector_cosine_ops);

-- the 3 nearest pages; :query_vector comes from the same embedding model
SELECT id, content, 1 - (embedding <=> :query_vector) AS cosine
FROM pages
ORDER BY embedding <=> :query_vector
LIMIT 3;

cross-encoder · reranker
سؤال مقابلة

سؤال قد تسمعه في المقابلة:

What is a bi-encoder, and why is it the standard choice for retrieval?

جواب قصير وجيد:

A bi-encoder maps the query and each document to vectors independently with the same model, usually by pooling token embeddings and normalizing. Because documents are encoded independently of the query, their vectors can be computed once and indexed, so search costs one encoder pass for the query plus a nearest-neighbor lookup. A cross-encoder is more accurate but must run on every query-document pair, so it is used to rerank a small candidate set.

سؤال قد تسمعه في المقابلة:

How are embedding models trained?

جواب قصير وجيد:

With contrastive learning on pairs such as question and relevant passage. For a batch of pairs, we compute the similarity matrix between all queries and all passages and apply softmax cross-entropy per row, where the diagonal is the positive and the other passages in the batch are negatives (the InfoNCE loss). A temperature scales the cosine similarities so the model can become confident, and hard negatives, passages that look relevant but are not, make the model learn finer distinctions.

سؤال قد تسمعه في المقابلة:

How do you search millions of vectors with low latency?

جواب قصير وجيد:

With approximate nearest-neighbor indexes. IVF clusters the vectors and searches only the clusters closest to the query; HNSW builds a navigable graph and walks it greedily toward the query. Both trade a small loss in recall for large speedups, controlled by parameters like the number of probed clusters or the search breadth. In practice you use a library or a vector database such as pgvector, FAISS, or a managed service.

سؤال قد تسمعه في المقابلة:

How would you choose an embedding model for a new domain?

جواب قصير وجيد:

Shortlist models by language support, size, latency, vector dimension, and maximum input length, using public benchmarks only as a starting point. Then build a small labeled set of real queries with their relevant documents and measure recall@k and MRR for each candidate. If none is good enough, consider fine-tuning on in-domain pairs with hard negatives.
